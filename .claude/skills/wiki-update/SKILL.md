# Update the tibo.dog wiki

The wiki is generated by `node build.mjs` from data dumped out of the deployed game. A systemd timer on pcstyle (`/home/exedev/tibodog-wiki`, every 30 min) applies new builds there and auto-deploys only `clean` ones. Builds that change data or logic are applied but left `unreviewed` in `data/builds.json` and not deployed, so several can pile up.

## 1. Find the real state

- Live wiki build: `curl -s https://tibodog-wiki.vercel.app/sources | grep -o 'main-[A-Za-z0-9_-]*\.js' | sort -u`.
- pcstyle build, history and timer log:
  ```sh
  ssh pcstyle.exe.xyz 'cd /home/exedev/tibodog-wiki && grep main data/build.json && XDG_RUNTIME_DIR=/run/user/$(id -u) journalctl --user -u tibodog-wiki-update --no-pager | grep status= | tail -15'
  ```
- List every `unreviewed` entry in `data/builds.json`. Older unreviewed entries can sit behind a reviewed one, so check the whole list, not only the latest entry.

The timer applies builds on pcstyle, so pcstyle is usually newer than the Mac. Compare modification times, then pull it before editing:

```sh
rsync -az --exclude node_modules --exclude dist --exclude .vercel --exclude .DS_Store --exclude .git pcstyle.exe.xyz:/home/exedev/tibodog-wiki/ ./
```

Never use `--delete`. If the Mac has edits that pcstyle lacks, merge them by hand.

If the live game build is newer than `data/build.json`, run `pnpm game:update` (or `pnpm game:check` to look first).

## 2. Review the diff since the last deployed build

Review from the last build that is live on the wiki to the current one, plus any older unreviewed builds. The per-build reports are in `.cache/<main>/report.md`.

```sh
node tools/diff-data.mjs .cache/<old main>/data .cache/<new main>/data
python3 -I tools/code-diff.py .cache/<old>/assets/sim-*.js .cache/<new>/assets/sim-*.js 60
python3 -I tools/code-diff.py .cache/<old>/assets/boot-*.js .cache/<new>/assets/boot-*.js 60
```

Config objects can move between the sim and boot chunks. `diff-data` then reports them as `no match in new build` and `new export` instead of diffing them. Match old and new objects by their keys and compare them yourself.

If `pnpm build` fails with `config object with keys ... not found`, look at `cfgBy` in `lib/data.mjs` first.

## 3. Fix the pages

- Tables built from `data/` update on their own. Check prose that hard-codes numbers or names: difficulty notes, POI text, controls, revive and stat notes in `pages/*.mjs`.
- Every quote has to point at the file that contains it. Use `cite(SIM, ...)` or `cite(BOOT, ...)` accordingly.
- `pages/notes.mjs` strings are template literals, so escape backticks as `` \` ``.
- Text about past builds belongs in `data/builds.json`, never in `pages/*.mjs`, because the updater rewrites chunk names there.

Then rebuild and check the quotes until nothing is unresolved:

```sh
pnpm build
node tools/check-quotes.mjs .cache/<new main>/assets --write
node tools/check-quotes.mjs .cache/<new main>/assets
```

`--write` only fixes renames. Moved and unresolved quotes need hand edits.

## 4. Write the history

For each unreviewed build, set `status: "reviewed"` and replace `changes` with a short, player-facing summary. Before you attribute a change to a build, check that build's `.cache/<main>/data`, because a cumulative diff hides which build introduced what. Write the file with `JSON.stringify(a, null, 1)` to keep the existing format. Right before you deploy, set `updated` to the current UTC time (`new Date().toISOString()`, seconds precision) on the newest build's entry and in `data/build.json`; the site shows it as "data synced" and in the Wiki updated column on `/versions`. Rebuild and confirm that `dist/versions.md` has no "Not reviewed yet".

## 5. Sync back, deploy, verify

1. Check that pcstyle has not applied a newer build since your pull: run `stat` on `data/build.json` and `data/builds.json` there. Then push your edits:
   ```sh
   rsync -azi --exclude node_modules --exclude dist --exclude .cache --exclude .vercel --exclude .DS_Store --exclude .git ./ pcstyle.exe.xyz:/home/exedev/tibodog-wiki/
   ```
2. Build there too. In non-interactive SSH, node, bun and vcx are not on PATH:
   ```sh
   ssh pcstyle.exe.xyz 'cd /home/exedev/tibodog-wiki && export PATH="$HOME/.bun/bin:$HOME/.local/bin:$PATH"; PATH="$(dirname "$(readlink -f "$(command -v node)")"):$PATH"; node build.mjs | tail -1'
   ```
3. A production deploy needs Adam's explicit approval for this run. Then run `vcx exec -p pc-style -- deploy --prod --yes`. On 2026-11-03 pcstyle's Vercel login returned "Not authorized" and the Mac worked. If one machine fails, try the other and tell Adam the timer cannot auto-deploy.
4. Verify on the live site: `/versions` shows the new `main-*.js` as current with no "Not reviewed yet", `curl -s https://tibodog-wiki.vercel.app/api/live-build` returns `"status": "up-to-date"`, and spot-check one changed page with `curl`.
5. `vercel promote` or a rollback turns off automatic production aliasing. Promote the next good deploy explicitly.

## 6. Commit

Commit the reviewed changes in this repo (`github.com/pc-style/tibodog-wiki`). Pushing to `main` needs Adam's okay for that job.

Stop and ask Adam if a logic change cannot be explained from the code, if pcstyle changed during your edit, or if the deploy fails on both machines.
